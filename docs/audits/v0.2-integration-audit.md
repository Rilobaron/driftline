## 2. Findings and fixes

### Critical

1. **Concurrent upserts raced on the candle identity constraint.**
   `upsert_candles` was check-then-insert: two workers syncing overlapping
   ranges both passed the existence check, then one crashed with
   `UniqueViolation` on `uq_candle_exchange` (reproduced on real PostgreSQL
   with 4 racing threads). "Idempotent upserts" held single-threaded only.
   **Fix:** single-statement `INSERT ... ON CONFLICT DO NOTHING` (dialect-native
   for PostgreSQL and SQLite), advisory pre-check retained for the exact
   "new rows" count, in-batch dedup added.
   **Evidence note:** psycopg3 reports `rowcount == -1` for this statement
   shape, so the count comes from the pre-check (exact when uncontended;
   best-effort under race — documented in code).
   **Tests:** `test_concurrent_upserts_no_duplicates` (PG),
   `test_unique_candle_constraint_enforced_at_db_level` (PG).
2. **Stream lease never actually locked.** `acquire_stream_lock` was
   read-modify-write (lost-update race: two workers could both return `True`)
   **and** ignored `lease_seconds`, stamping `locked_until = now` — every
   lease was born expired and immediately stealable. The "never sync
   concurrently" guarantee was void.
   **Fix:** atomic conditional `UPDATE ... WHERE id AND (unlocked OR expired
   OR self-owned)` (compare-and-swap; same truth table, serialized by the
   database), `locked_until = now + lease_seconds`; `release_stream_lock`
   re-reads before clearing so a stale handle cannot wipe a legitimately
   stolen lease; `get_or_create_stream` survives creation races via
   rollback + re-select.
   **Tests:** `test_lease_semantics.py` (truth table incl. renewal/steal),
   `test_competing_workers_exactly_one_owner` (8 threads, barrier, PG),
   `test_concurrent_stream_creation_single_row` (PG).

### High

3. **Alembic could not target PostgreSQL.** `alembic/env.py` rewrote
   `+psycopg` → `+psycopg2`, but only psycopg3 is installed — every PG
   migration failed with `ModuleNotFoundError`. **Fix:** pass the URL through
   unchanged. Verified by applying migrations to real PG.
4. **Migration/metadata drift (`alembic check` failed).** Three diffs:
   `candles.exchange` nullable in migrations vs `NOT NULL` in models;
   `market_streams.unresolved_gaps` likewise; redundant `UNIQUE(id)` on
   `sync_runs` (PK already unique) confusing autogenerate matching.
   **Fix:** `nullable=False` on both columns in migration + models (all
   writers store values, all readers are `or []`-tolerant — grep-verified),
   removed the redundant constraint from both. `alembic check` is now clean.
5. **Alembic env var clobbered programmatic config.** `env.py` let
   `DATABASE_URL` override an explicitly configured URL, so migration tests
   silently ran against SQLite (the suite's `DATABASE_URL`) instead of the
   target database. **Fix:** precedence explicit-config → env → default.

### Medium

6. **Any successful sync marked `bootstrap_done=True`**, even bounded partial
   runs — the scheduler would switch to incremental mode and ancient history
   would never backfill. **Fix:** set the flag only when stored depth reaches
   `bootstrap_target` or the provider is exhausted with zero gaps (aligned with
   the quality module's existing depth-aware derivation).
   **Tests:** `test_bootstrap_not_done_after_bounded_partial_run`,
   `test_bootstrap_done_when_provider_exhausted`.
7. **Manual API syncs shared one static lock owner** (`"api-manual"`): two
   concurrent `POST /market/sync` calls renewed instead of conflicting (no
   409). **Fix:** unique `api-manual:{id}` owner per request. Unvalidated
   `exchange` on the same routes could also split stream identity
   (`"Binance"` vs `"binance"`); now validated/normalized.
8. **`sort_entries` ranked `None` metrics first when descending** (the
   default), contradicting its "None sorts last" contract — misleading
   dashboard ordering. **Fix:** partition then sort; `None` always last.
   **Test:** `test_sort_entries_none_metrics_always_last`.
9. **Market identity split by case.** `"btc/usdt"`/`"1H"` missed DB rows and
   could create parallel datasets. **Fix:** `validate_timeframe` lowercases;
   provider normalizes symbol/timeframe before fetch; `_resolve_candles`
   normalizes before DB lookup. **Tests:** normalization unit + API test.

### Low / Informational

- Walk-forward all-`None` objective (e.g. Sharpe on flat markets) skipped folds
  with a misleading `min_trades` message → now freezes the first candidate
  with an explicit "undefined objective" warning. Walk-forward also fails fast
  when `train_window` is smaller than a candidate's warmup (previously a
  mid-run `ValueError`).
- Windowed evaluations (splits, walk-forward folds) now warn on open end
  positions and state that trade statistics exclude marked-unrealized value
  (closes the discoverability gap on the reported carry-forward limitation).
- Risk manager rejects NaN/negative caller state (`cash`, `equity`,
  `position_qty`); ops-token comparison uses `hmac.compare_digest`.
- `QualityReport.duplicates/invalid` are hardcoded `0` (not computed) —
  left unchanged to avoid breaking the schema; consumers should not read them
  as measured values.
- Weekly (`1w`) candle grids anchor to the 1970-01-01 Thursday epoch and may
  mismatch exchange week boundaries; hourly/daily anchoring verified correct.
  Only `1h` streams are configured.
- `GET /market/streams` and `/market/health` auto-create preset rows (read
  with idempotent write side effects — intentional, harmless).
- `DRIFTLINE_OPS_TOKEN` is empty by default (documented local-dev posture);
  must be set in any shared deployment. No secrets found in the tree; `.env`
  absent; DBs/venv git-ignored.

## 9. Remaining risks & v0.2c guidance

1. **Paper-trading reuse of leases/upserts is now safe** (atomic lease honors
   `lease_seconds`; upserts race-free). v0.2c must use **unique owner IDs per
   trader instance** (never a static string) and must not assume
   `upsert_candles` counts are exact under concurrency.
2. **Experiments table has no exchange column** — multi-exchange research rows
   rely on `record` JSON + fingerprint (which is exchange-scoped). Keep it
   that way; do not "normalize" provenance out of the fingerprint.
3. **Concurrent schema guard:** v0.2c migrations must branch from
   `0003_merge_v02` (the single head) — verify with `alembic heads`.
4. **Local worker on a v0.1 database:** run `alembic upgrade head` first
   (Compose already does; `python -m driftline.worker` alone only runs
   `create_all`, which cannot add the `exchange` column).
5. **Known non-goals left as-is:** hardcoded quality zeros, weekly grid
   anchoring, flat-rate costs, single position, advisory-only AI posture.
